# NYPC Master 예선: 전략 게임 AI 봇

| 항목 | 내용 |
|---|---|
| **기간** | 2026.07 |
| **형태** | 대회 참가 · 팀 블루칩스 (2인) |
| **기술** | Python · 다익스트라 · BFS · 상태 기계 |

---

## 1. 문제
턴제 전략 게임에서 러시나 타이밍 공격처럼 **서로 다른 전략을 쓰는 여러 상대에게 모두 안정적으로 이기는** 봇을 만드는 과제였습니다.

## 2. 접근: 규칙 기반 의사결정
학습 기반 방식 대신, 매 턴 상태를 판정하고 우선순위에 따라 행동하는 **규칙 기반 구조**를 택했습니다.

| 구성 | 구현 내용 |
|---|---|
| **상태 파싱** | 매 턴 이벤트(UPGRADE · TRAIN · MOVE · DAMAGE · SIEGE)를 반영했습니다. 상대의 지출을 역추적해 *볼 수 없는 상대 골드와 수입을 추정*했습니다 |
| **사전 계산** | 게임을 시작할 때 모든 거점 간 최단 이동 비용(다익스트라)과 최소 홉 수(BFS)를 미리 계산해, 시간 제한 안에서 여유를 확보했습니다 |
| **의사결정** | 러시 감지 상태 기계(`NORMAL → WARNING → DEFENSE → RECOVER`)를 만들었습니다. 위협도에 따라 수비 병력을 동적으로 산정하고, 중앙 경합 거점을 포함한 확장 순서를 설계했습니다 |
| **안정성** | 단계마다 마감 시간을 검사하고 `try/except`로 예외를 막았습니다. 어떤 상황에서도 빈 명령이라도 내보내서 몰수패를 막았습니다 |

## 3. 개발 방식 · LLM 활용
- **리플레이 분석 → 가설 → 구현 → 재대전** 사이클을 반복했습니다.
- LLM은 아키텍처 설계, 함수 구현, 디버깅에 활용했습니다. 다만 LLM의 추론이 실제 대전 결과와 어긋나는 경우가 있었습니다. 그래서 **모든 변경을 실제 대전으로 검증하고, 이긴 로직만 남겼습니다.**

## 4. 회고
- 러시 방어를 강화하면 경제가 뒤처지는 식으로, 하나를 고치면 다른 게 깨졌습니다. *모든 상대에게 무난한 균형점*을 찾는 게 가장 어려웠습니다.
- 다음에는 리플레이를 승률, 자원 차이, 거점 수 같은 정량 지표로 자동 집계해 **데이터 기반으로 튜닝**하고 싶습니다.
