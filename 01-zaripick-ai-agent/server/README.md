# 자리픽 API 서버

`seoul_db.db`(서울 상권 데이터, 26개 테이블)를 읽어 상권 지표를 제공하고,
**Gemini · GPT · Claude** 중 아무거나 붙여 분석 해설과 AI 상담 에이전트를 제공하는 API 서버입니다.
**외부 의존성 0**, Node 내장 모듈만 씁니다.

## 요구사항

- **Node 22.5 이상** (내장 `node:sqlite` 사용). 확인: `node --version`
- `seoul_db.db` 가 프로젝트 루트에 있을 것

## 시작하기

```bash
cd server
copy .env.example .env
npm run build:cache
npm start
```

브라우저에서 http://localhost:8787 을 열면 됩니다 (서버가 프런트엔드까지 서빙합니다).

> `npm install` 은 필요 없습니다. 설치할 패키지가 없습니다.

## API 키 설정 (AI 해설 · 챗봇)

**Gemini · GPT · Claude 중 아무거나 하나**만 넣으면 켜집니다. 프런트엔드는 수정할 게 없고 서버만 재시작하면 됩니다.

```env
GEMINI_API_KEY=AIza...      # https://aistudio.google.com/apikey
OPENAI_API_KEY=sk-...       # https://platform.openai.com/api-keys
ANTHROPIC_API_KEY=sk-ant-...
```

여러 개를 넣으면 `AI_PROVIDER_ORDER` 순서대로 **키가 등록된 첫 프로바이더**를 쓰고,
호출이 실패하면 다음 프로바이더로 자동 전환합니다(`AI_FAILOVER=true`).
특정 하나만 쓰려면 `AI_PROVIDER=gemini` 처럼 지정하세요.

> 모델명은 각 사가 수시로 바꿉니다. `GEMINI_MODEL` / `OPENAI_MODEL` 기본값이 거부되면
> 콘솔에서 현재 사용 가능한 모델명을 확인해 `.env` 에 넣으세요.

**키가 없어도 서비스는 그대로 동작합니다.** 아래처럼 자동 전환됩니다.

| 상황 | 생성 방식 | 응답 `by` 값 |
|---|---|---|
| 키 있음 · 호출 성공 | LLM이 관측 지표를 해석 | `ai` |
| 키 있음 · 전 프로바이더 실패 | 규칙 기반으로 폴백 | `rule-fallback` |
| 키 없음 | 규칙 기반 | `rule` |

어느 경로든 **응답 스키마와 숫자는 동일**합니다. 수치는 전부 서버가 계산하고 LLM은 해석만 하며,
프롬프트에서 매출 예측과 새 숫자 생성을 금지하고 있습니다.

```bash
  -H "content-type: application/json" \
  -d '{"industry":"cafe","goal":"traffic","mode":"visit","budget":15000,"area":15,"equity":8000}'

curl -X POST http://localhost:8787/api/chat \
  -H "content-type: application/json" \
  -d '{"messages":[{"role":"user","content":"강남에서 1억 5천으로 카페 자리 찾아줘"}]}'
```

## AI 상담 에이전트

`/api/chat` 은 LLM에게 답을 직접 쓰게 하지 않습니다.
**도구를 고르게 하고, 숫자는 서버가 계산해 되돌려준 뒤, 그 결과만 문장으로 옮기게** 합니다.
그래서 어떤 모델을 쓰든 수치가 동일합니다.

| 도구 | 하는 일 |
|---|---|
| `list_options` | 지원 업종·목적·운영형태·자치구 유효값 |
| `search_areas` | 조건 → 적합도 순 상권 추천 |
| `get_area_detail` | 특정 상권 상세 지표 (지역명 부정확해도 매칭) |
| `compare_areas` | 2~4곳 동일 조건 비교 |
| `simulate_finance` | 소요자금·조달 조합·손익분기 매출선 |
| `explain_metric` | 지표 산출식·데이터 출처·한계 |

응답에는 실행한 도구 목록(`trace`)이 함께 오고, 화면에는 이것이 칩으로 표시됩니다.

키가 없으면 **규칙 기반 라우터**가 같은 도구를 호출해 같은 스키마로 답합니다.
업종·예산·지역을 대화 이력에서 거슬러 찾아내므로 후속 질문("거기 자금은?")도 이어집니다.

요청 본문에 `context.cond` 를 넣으면 화면에서 설정한 분석 조건을 기본값으로 씁니다.

## SGIS 전국 통계 연동

`seoul_db` 는 서울 전용입니다. SGIS(통계청 통계지리정보서비스)는 같은 성격의 지표를
**전국 시군구·읍면동 단위**로 제공하므로 전국 확장의 기준 데이터가 됩니다.

```env
SGIS_SERVICE_ID=발급받은_서비스ID
SGIS_SECURITY_KEY=발급받은_보안키
```

발급: https://sgis.kostat.go.kr/developer (무료 · 일 50,000회)
**키가 없으면 관련 기능만 꺼지고 서울 분석은 그대로 동작합니다.**

### 업종 매핑

SGIS 사업체통계는 테마코드로 업종을 지정합니다. 자리픽 8개 업종에 이렇게 대응시켰습니다.

| 자리픽 업종 | SGIS 테마코드 |
|---|---|
| 카페·디저트 | 5010 카페 |
| 베이커리 | 5006 제과점 |
| 한식·분식 | 5001 한식 + 5004 분식 |
| 주점·호프 | 5009 호프 및 간이주점 |
| 미용·뷰티 | 1008 미용실 + D005 피부/미용 |
| 학원·교육 | 1003 교습학원 + 1004 어학원 + 1005 예체능학원 |
| 헬스·필라테스 | F001 생활체육시설 |
| 편의점·무인 | 2003 편의점 |

여러 테마에 걸치는 업종은 합산합니다.

### 구현 시 주의한 점

1. **SGIS는 실패해도 HTTP 200을 줍니다.** 반드시 `errCd` 를 확인해야 합니다.
2. **토큰은 4시간 유효**하며 응답의 `accessTimeout`(만료 epoch ms)을 그대로 씁니다.
   만료 5분 전에 미리 갱신하고, 동시 요청이 중복 발급하지 않도록 발급 Promise를 공유합니다.
   갓 발급된 토큰이 간헐적으로 거부되는 경우가 있어 1회 재발급 후 재시도합니다.
3. **행정구역 코드 체계가 seoul_db 와 다릅니다.** SGIS는 자체 코드(서울=11, 부산=21,
   성동구=11040)를 쓰고 seoul_db 는 행안부 코드를 씁니다. **직접 조인하면 안 됩니다.**
   SGIS는 서울 밖 지역 조회에만 사용합니다.
4. **일일 한도를 아끼려고 결과를 메모리에 캐시**합니다(기본 12시간, `SGIS_CACHE_MIN`).
   행정구역 인덱스(시도 17 + 시군구 252)는 최초 1회만 구축합니다(약 0.7초).

### 서울과 전국의 차이

| | 서울 (seoul_db) | 전국 (SGIS) |
|---|---|---|
| 단위 | 상권 1,030곳 | 시군구 |
| 유동인구 | 있음 | 없음 |
| 임대료·공실률 | 있음 | 없음 |
| 폐업률 | 있음 | 없음 |
| 적합도 점수 | 산출 | **산출하지 않음** |

전국 조회 결과에는 이 한계를 명시하고, 서울 점수와 직접 비교하지 않도록
도구 응답과 시스템 프롬프트 양쪽에 제약을 걸어 두었습니다.

## 서비스 지역 범위 (분석 등급)

지역마다 확보한 데이터가 달라 제공 수준이 다릅니다. 이를 숨기지 않고 **등급으로 드러냅니다.**
정의는 [`src/scope.mjs`](src/scope.mjs) 한 곳에 있고 화면·API·에이전트가 모두 이걸 따릅니다.

| 등급 | 지역 | 단위 | 제공 |
|---|---|---|---|
| **정밀 분석** | 서울 | 상권 1,030곳 | 6축 적합도 점수 · 초기비용 · 자금 설계 · PDF |
| **기본 통계** | 전국 17개 시도 · 252개 시군구 | 시군구 → **행정동** | 인구·연령 구성 · 업종별 점포 수 · **점포당 월매출** · 유동인구·소득·소비 · 개폐업률 · **임대료·권리금·초기비용·자금계획** |

기본 통계 지역은 **교통·생활인프라 지표가 없어 적합도 6축 점수를 산출하지 않습니다.**
(임대료는 한국부동산원 연동으로 확보돼 초기비용과 자금 계획은 냅니다.)
화면에서도 코인을 차감하지 않고, 결과에 "서울 점수와 직접 비교하지 말 것"을 명시합니다.

### 왜 전국을 열었나

처음에는 서울 + 6대 광역시였습니다. SGIS(인구·사업체)·LOCALDATA(개폐업)·소상공인365(매출·유동인구)가
**모두 전국을 덮는다**는 것이 확인되면서 광역시로 묶어 둘 이유가 없어졌습니다.
여전히 없는 것은 임대료 하나뿐이라 등급은 그대로 둘로 유지합니다.

### 행정동까지 내려간다

시군구를 고르면 그 안의 읍면동 목록이 따라 붙고, 동 하나를 고르면 그 동만 봅니다.
동 단위에서는 **시군구 안에서 몇 위인지**를 함께 보여 줍니다 — 절대값보다 읽기 쉽습니다.

```
GET /api/regions?cd=21090        → 해운대구의 읍면동 목록
GET /api/region?admCd=21090xxx   → 8자리면 행정동, 5자리면 시군구로 해석
```

다만 **인허가 데이터에는 행정동 구분이 없습니다.** 동을 봐도 개·폐업은 시군구 전체 값이라,
응답에 `개폐업_기준` 을 실어 화면이 그 사실을 그대로 표시하게 했습니다.

## LOCALDATA 전국 개·폐업 연동

SGIS는 전국 '사업체 수'는 주지만 **폐업률을 주지 않습니다.**
LOCALDATA(행정안전부 지방행정 인허가)가 인허가일·폐업일·영업상태를 제공해
전국에서 개업률·폐업률을 산출할 수 있는 유일한 무료 경로입니다.

```env
LOCALDATA_API_KEY=발급받은_인증키
```

**적재하지 않고 요청 시점에 조회합니다.** 필요한 건 건수뿐이라
`numOfRows=1` 로 부르고 `totalCount` 만 읽습니다.

### cond[필드::연산자] 문법 — 이 API의 핵심

필터가 일반적인 파라미터명이 아니라 아래 형태입니다. 이걸 모르면
`localCode`, `opnAtmyGrpCd` 같은 이름을 아무리 넣어도 **조용히 무시**되고
전체 건수가 그대로 돌아옵니다.

| 조건 | 예시 |
|---|---|
| 자치단체 | `cond[OPN_ATMY_GRP_CD::EQ]=3010000` |
| 영업상태 | `cond[SALS_STTS_CD::EQ]=01` (01 영업 / 03 폐업) |
| 인허가일 | `cond[LCPMT_YMD::GTE]=2025-01-01` |
| 폐업일 | `cond[CLSBIZ_YMD::LT]=2026-01-01` |
| 업태명 | `cond[BZSTAT_SE_NM::LIKE]=커피숍` |

조건은 겹쳐 쓸 수 있습니다. 응답 포맷 파라미터도 `resultType` 이 아니라 **`returnType`** 입니다.

### 실측으로 확인한 함정 세 가지

1. **날짜는 하이픈 형식이어야 합니다.** 저장값이 `2026-05-31` 형태라
   `20250811` 을 주면 문자 비교에서 `'-'(0x2D) < '0'(0x30)` 이 되어
   **그 해 자료가 통째로 빠집니다.** 성동구 제과점 폐업이 28건에서 16건으로 줄었습니다.

2. **날짜 필터의 실제 정밀도는 연 단위입니다.** 같은 해 안에서는 날짜를 바꿔도
   결과가 변하지 않습니다(`GTE 2025-01-01` = `GTE 2025-12-31`).
   그래서 `GTE` + `LT` 로 **연 경계를 닫아** 쓰고, 기준을 '직전 완결 연도'로 잡았습니다.
   "최근 1년"으로 두면 조회 시점에 따라 창이 12~24개월로 변해 폐업률이 연중 부풀어 오릅니다.

3. **미용업(beauty_salons)만 조건과 무관하게 항상 30초쯤 걸립니다.**
   다른 서비스는 0.1~2.4초입니다. 타임아웃을 45초로 둔 이유입니다.
   실패해도 예외를 던지지 않고 `조회실패` 플래그를 돌려줘, 지표 하나 때문에
   화면 전체가 무너지지 않게 했습니다.

### 자치단체코드는 API 에서 직접 만든다


참고문서로 받은 `개방자치단체코드_영업상태코드.xlsx` 는 **행정구역 개편 전 기준이라 쓰지 않습니다.**
실측으로 드러난 어긋남:

- **광주광역시 → 전남광주통합특별시** 통합으로 코드가 `36xxxxx` → `58xxxxx` 로 바뀌었습니다.

그래서 제과점·헬스장 두 서비스를 전량 훑어 `코드 ↔ 주소` 대응을 실데이터에서 수집합니다.
한 서비스만 보면 그 업종이 없는 자치구가 통째로 빠집니다(수원시 4개 구 중 권선구만 잡혔습니다).
현재 **230곳**이며, 전 코드가 실제 응답을 돌려주는 것까지 확인했습니다.

지역명 조회에서 걸린 함정 두 가지:

- 자치단체코드는 **'시' 단위**입니다. `3740000` 하나가 수원시 권선·팔달·장안·영통을 모두 덮습니다.
  일반구는 라벨에 넣지 않습니다.
- 시도 힌트는 **낱말 첫머리에서만** 찾아야 합니다. 느슨하게 보면 `해운대구` 안의 `대구` 가 걸려
  대구광역시로 잘못 몰립니다. 같은 이유로 `광주광역시 서구` 가 서울 강서구로 새기도 했습니다.

## 소상공인365 매출 연동

`src/sbiz.mjs`. SGIS 는 사업체 '수', LOCALDATA 는 '개·폐업'을 주지만
**얼마나 파는지는 어느 쪽에도 없었습니다.** 소상공인시장진흥공단 소상공인365가
전국 행정동 × 업종의 **점포당 월평균 매출**을 제공해 그 자리를 메웁니다.
유동인구·소득·소비·직장인구·주거인구·세대수도 같은 계열로 옵니다.

### 발급받은 certKey 는 데이터 키가 아닙니다

이게 이 연동에서 가장 헷갈리는 지점입니다. 발급 화면이 "API URL"이라고 부르지만
그 주소는 SPA 해시 라우트고, 인증키는 라우터 가드가 검증합니다.

```
POST /pub/api/apics/checkApiCertVl  { apiCertKeyVl: <certKey> }
  → "simple"          // 라우트명만 돌아온다
```

즉 **11개 키 = 11개 분석 '화면' 접근 권한**이며 JSON 데이터는 나오지 않습니다.
정작 그 화면들이 쓰는 `/gis/api/*` 는 **인증을 요구하지 않습니다.**
그래서 데이터는 gis 쪽에서 받고, certKey 는 `screenUrl()` 딥링크에만 씁니다.

### 조회 방식

지역코드가 아니라 **지도 bbox(EPSG:5181 미터)** 로 조회합니다.

```
GET /gis/api/getMapRadsSaleAmt.json
    ?mapLevel=3&substr=8&bzznType=1
    &minXAxis=…&maxXAxis=…&minYAxis=…&maxYAxis=…
    &upjongCd=I21201
```

| 지표 | 엔드포인트 |
|---|---|
| 점포당 매출 | `getMapRadsSaleAmt.json` |
| 점포 수 | `getMapRadsStorCnt.json` |
| 유동인구 | `getMapRadsPopCnt.json` |
| 소득 / 소비 | `getMapRadsWholEarnAmt` / `getMapRadsWholCnsmpAmt` |
| 직장 / 주거 / 세대 | `getMapRadsWrcpplCnt` / `getMapRadsWholPpltnCnt` / `getMapRadsHhCnt` |

### 실측으로 확인한 함정 네 가지

1. **`bzznType=1` 이 없으면 전부 500** 입니다. `Rads` 계열이 행정구역 단위,
   `Bizon` 계열이 주요상권 단위입니다.

2. **업종코드는 소분류(6자리) 하나만 받습니다.** 중분류(`I201`)나 복수 지정
   (`I21201,I21008`)은 오류 없이 **0건**이 옵니다. 그래서 자리픽 업종 하나가
   여러 코드면 각각 부르고 **점포수 가중평균**으로 합칩니다 — 매출이 '점포당 평균'이라
   단순 평균을 내면 틀립니다.

3. **행정동 하나가 여러 행으로 옵니다.** 값은 같은데 `storeCnt` 만 정상값과 그 3배가
   섞여 있습니다(지도 마커가 겹쳐 그려지는 탓). 최솟값이 늘 정상값이었습니다.

4. **몰아서 부르면 연결을 끊습니다(ECONNRESET).** 시군구 bbox 를 요청마다
   행정동 경계로 만들다가 실제로 차단됐습니다. 그래서 인덱스를 미리 만들어 둡니다.

### 원자료의 이상값 처리

점포가 적은 칸은 `"- 만원"` 으로 가려져 옵니다. 이건 정상 동작이라 값 없음으로 둡니다.

문제는 **비상식적으로 큰 값**입니다. 강남구 개포2동 편의점 17곳에 277,157만원,
즉 점포당 월 27.7억원이 실려 옵니다. 같은 동의 카페·한식·미용은 정상이라
동 전체가 아니라 **(행정동 × 업종) 칸의 결함**입니다.

중앙값 배수로 거르는 방법은 못 씁니다 — 강남 편의점처럼 결함 칸이 여럿이면
중앙값 자체가 오염됩니다. 그래서 **점포당 월매출 3억원**이라는 절대 상한을 두고,
넘는 칸은 평균에서 빼되 **몇 개 동을 뺐는지 화면에 표기**합니다.
적용 전후: 강남구 편의점 35,363만원 → **5,017만원** (22개 동 중 7개 제외).
같은 구의 청담동 4,896 · 압구정동 4,776 과 맞아떨어집니다.

### 행정동 코드는 이름으로 다리를 놓는다

세 데이터가 행정동을 서로 다르게 셉니다. 같은 명동을 **SGIS 는 `11020550`,
소상공인365 는 `11140550`** 이라 부릅니다. 뒤 4자리가 우연히 맞는 동도 있지만
어긋나는 동이 있어서(다산동 `700` vs `625`) 코드로 맞추면 **조용히 다른 동을 집습니다.**
그래서 시군구를 먼저 고정하고 **이름으로** 찾습니다.

전국 3,559개 읍면동으로 재 보면 **3,552개(99.8%)** 가 이어집니다. 그 과정에서 걸린 것들:

- **광주·전남 통합.** 소상공인365·LOCALDATA 는 둘을 `전남광주통합특별시` 하나로 묶었습니다.
  시도 힌트를 '먼저 걸린 하나'로 잡으면 **전남 22개 시군구·297개 동이 통째로 사라집니다.**
  힌트를 여러 개 가질 수 있게 고쳤습니다.
- **정식 시도명.** `충청북도청주시상당구` 처럼 물으면 접미사 규칙(`특별시`·`광역시`)에 안 걸립니다.
  후보들의 시도명으로도 한 번 더 떼어 냅니다.
- **인천 행정구역 개편.** 중구·동구·서구가 폐지되고 영종구·제물포구·서해구·검단구가 생겨
  옛 구 이름으로는 시군구부터 안 잡힙니다. 시도만 붙잡고 동 이름으로 찾되,
  **이름이 하나만 맞을 때에만** 인정합니다 — 조용히 틀리느니 없다고 하는 편이 낫습니다.
- **일반구.** 소상공인365 자치단체는 시 단위라 `수원시` 하나가 4개 구를 덮습니다.
- **읍 승격·동 통합.** `대소면`→`대소읍`, `박달1동`→`박달동`. 숫자를 떼고
  읍·면·동 접미사를 뭉갠 느슨한 키로 마지막에 한 번 더 맞춥니다.

남은 7건은 양쪽 개편 시점이 달라 대응이 없는 동입니다.

### 서울 상권에도 붙는다

`cache/areas.json` 의 상권이 이미 `admCd`(행정동 8자리)를 들고 있고
**소상공인365와 같은 체계**라, 서울 상권 리포트에도 실매출을 그대로 붙일 수 있습니다.
심층 리포트 5-3-1 에서 '원리금 상환 포함 필요 매출선'과 나란히 놓아
목표선이 현실적인지 대조하게 했습니다.

적합도 6축 점수에는 **넣지 않았습니다.** 산식이 이미 확정돼 있고,
행정동 평균이라 상권 단위 점수와 해상도가 다르기 때문입니다. 참고 수치로만 씁니다.

### 순위는 시군구 안에서의 상대 평가

각 축은 **선택한 시군구의 행정동들 사이 백분위**입니다.
시군구마다 1등이 100점 근처가 되므로 **다른 시군구의 점수와 견주면 안 됩니다.**
응답의 `한계` 필드가 이 문장을 그대로 들고 다닙니다.

값이 없는 축은 0점으로 채우지 않고 **빼고 남은 가중치로 다시 나눕니다.**
0으로 채우면 자료가 없다는 이유만으로 순위가 떨어집니다.

### 임대료·폐업률은 순위를 가르지 않는다

둘 다 시군구 단위라 같은 시군구 안에서는 모든 행정동이 같은 값입니다.
순위 대신 '이 지역에서 창업이 가능한가'(예산 초과 여부)를 판정하는 데 씁니다.

서울은 seoul_db 의 임대료를 씁니다 — 다만 그것도 **자치구 단위**입니다
(성동구 29개 상권이 전부 18만원). 행정동 단위 임대료는 어느 기관도 공개하지 않습니다.
화면의 '공통 조건'과 각 행정동 카드가 **같은 값**을 쓰도록 서버가 실제 적용값을 내려보냅니다.

### 시도 전체는 받지 않는다

행정동 순위는 시군구 하나를 정해야 매깁니다. 시도 전체를 훑으려면
시군구 수만큼(서울 25회) 조회가 필요해 응답이 너무 느려집니다.
시군구 하나는 약 1.5~2.5초입니다.

### 지역 해상도를 숨기지 않는다

R-ONE 의 단위는 행정구역이 아니라 자체 **상권**입니다(`광주>금남로/충장로`).
시군구와 1:1로 맞지 않아 두 단계로 줍니다.

1. 시군구 이름이 상권명에 들어 있으면 그 상권들의 평균 — **72곳**
2. 아니면 그 시도의 대표값 — **180곳**

어느 쪽을 썼는지 항상 `기준` 에 적어 내려보내고 화면에도 그대로 씁니다
("부산 지역 상권 1곳 평균" / "제주 시도 평균"). 전국 252개 시군구를 **100% 덮습니다.**

주의: SGIS 는 지역명을 `부산광역시해운대구` 처럼 **붙여서** 줍니다.
공백으로만 자르면 시도까지 남아 상권 매칭이 조용히 빗나가고 늘 시도 평균으로 떨어집니다.

### 권리금을 총 소요자금에 넣었다

실제로 나가는 목돈이라 빼 두면 자금 계획이 그만큼 헐거워집니다.
면적 비례는 `㎡당 평균`으로 하되, 없으면 **중위수**를 씁니다 — 평균은 소수의 고액 사례에 끌려갑니다.

`/api/analyze` 와 `/api/deep` 이 **같은 인자**로 권리금을 조회합니다.
한쪽에만 넣으면 같은 상권의 개설비용이 목록과 리포트에서 달라집니다(실제로 그렇게 어긋났습니다).
권리금은 시도 단위 값이라 서울 전체가 조회 한 번으로 끝납니다.

적합도 6축 점수에는 **넣지 않았습니다.** 산식이 이미 확정돼 있고 지역 평균이라 해상도가 다릅니다.

### 전국에서 자금 계획이 가능해졌다

임대료가 생기면서 서울 밖에서도 초기비용과 조달 계획을 냅니다.
`/api/region` 에 `area`·`equity` 를 넘기면 `자금` 이 함께 옵니다.

여전히 **6축 점수는 서울만**입니다 — 교통·생활인프라 지표가 서울에만 있습니다.
등급 구분이 남아 있는 이유가 임대료에서 이 두 축으로 바뀌었을 뿐입니다.

## 데이터 파이프라인

`npm run build:cache` 가 `seoul_db.db` 를 읽어 `cache/areas.json`(약 1.9MB)을 만듭니다.
유동인구 테이블만 370만 행이라 요청마다 스캔하지 않고 사전 집계합니다.
**DB가 갱신되면 이 명령을 다시 실행**하세요.

### 알아둘 데이터 한계

1. **매출 데이터는 골목상권에만 있습니다.** `trade_area_sales` 는 골목상권 1,087곳만 수록하고
   발달상권·관광특구·전통시장은 0건입니다. 이 경우 같은 자치구 골목상권 중앙값으로 대체하고
   `salesIdxSource` 에 `gu_avg`(자치구 대체) / `seoul_avg`(서울 대체) / `observed`(관측값)를 표시합니다.
   DB가 임대료를 다루는 방식(`match_type`)과 같은 원칙입니다.
2. **권리금 데이터가 없습니다.** 공개 데이터가 없어 비용 산출에서 제외했고, 리포트에도 표시하지 않습니다.
3. **보증금은 가정값입니다.** 월 임대료 × 10개월로 계산합니다.
   DB의 `est_deposit_per_pyeong` 은 전환율 기반 *환산보증금*이라 실제 계약 보증금보다 훨씬 큽니다.
4. **인테리어·운영비 단가는 업종 표준 가정값**이며 DB 관측값이 아닙니다.
   리포트에서 관측값과 구분해 표기합니다.
5. 매출·수익은 **예측하지 않습니다.** 점포별 편차가 커서, 대신 고정비에서 역산한
   *손익분기 필요 매출*만 제시합니다.
