# 머신러닝 과제 (scikit-learn · XGBoost)

3학년 1학기 머신러닝 수업 과제입니다. 매 과제는 실제 데이터를 받아 **전처리 → 피처 설계 → 모델 비교 → 튜닝 → 제출 파일 생성**까지 진행하는 예측 대회 형식이었습니다.

| 과제 | 주제 | 데이터 | 평가 지표 | 최종 결과 |
|:-:|---|---|:-:|---|
| [HW1](hw1/hw1.ipynb) | 타이타닉 생존 예측 | 799명 | Accuracy | 로지스틱 회귀 · Val Acc **85.5%** |
| [HW2](hw2/hw2.ipynb) | 갑상선암 진단 분류 (불균형) | 77,159건 · 양성 12% | Weighted F1 | Bagging-DT · F1 **0.861** |
| [HW3](hw3/hw3.ipynb) | 항공편 지연 확률 예측 | 80만 건 (라벨 약 20만) | Log-Loss | XGBoost · Hold-out **0.4376** |

## HW1 · 타이타닉 생존 예측: 로지스틱 회귀
**한 모델을 두고 피처를 하나씩 바꿔 가며 무엇이 성능을 올리는지 확인했습니다.**

- **누수 방지**: 먼저 train/validation을 나누고, 결측치(Age, Embarked)는 *train의 평균과 최빈값으로만* 채웠습니다.
- **5단계 실험**: 각 단계마다 규제 강도 `C`와 `max_iter`를 다시 탐색하고, 혼동행렬·Log-Loss·ROC·PR 곡선으로 비교했습니다.

  | 실험 | 변경 | Val Acc |
  |:-:|---|:-:|
  | 1 | 기본 피처 (성별·객실 등급·나이·요금·가족 수) | 84.0% |
  | 2 | + 탑승 항구(Embarked) | 83.0% |
  | 3 | 요금(Fare) 로그 변환 (오른쪽 꼬리 분포 완화) | 82.5% |
  | 4 | 2 + 3 결합 | 84.5% |
  | 5 | **+ 이름에서 호칭(Mr/Mrs/Miss/Master/Rare) 추출** | **85.5%** |

- **클래스 가중치 실험**: 생존자를 놓치는 오류를 줄이려고 `class_weight='balanced'`를 적용했습니다. 재현율은 올랐지만 정확도와 Log-Loss가 나빠져서 최종 모델에는 쓰지 않았습니다.

## HW2 · 갑상선암 진단 분류: 불균형 데이터
**양성이 12%뿐인 데이터에서, 모델보다 *불균형 처리와 평가 방식*이 결과를 더 크게 좌우했습니다.**

- **피처 설계**: 국가 10개를 대륙 4개로 묶어 원-핫 차원을 줄였습니다. 호르몬 수치 간 관계를 반영한 파생 변수 `T3/T4 비율`과 `TSH × 나이`를 만들었습니다.
- **리샘플링**: Stratified 5-Fold의 *각 fold 학습 데이터 안에서만* SMOTEENN(오버샘플링 + 노이즈 제거)을 적용해 검증 데이터가 오염되지 않게 했습니다.
- **모델 비교 6종**: LR · KNN · Decision Tree · Linear SVM · Random Forest · Bagging(DT). RF는 GridSearchCV로 튜닝했습니다.
- **피처 선택**: 10-Fold 평균 트리 중요도로 상위 피처 10개만 남겨 다시 학습했습니다.
- **임계값 조정**: PR 곡선에서 F1이 가장 높은 임계값(0.5 대신 약 0.52~0.60)을 골랐습니다.

| 모델 | 기본 | 튜닝 · 임계값 조정 후 |
|---|:-:|:-:|
| Linear SVM | 0.61 | – |
| KNN | 0.69 | – |
| Logistic Regression | 0.73 | – |
| Random Forest | 0.75 | 0.861 |
| **Bagging (Decision Tree)** | 0.78 (단일 DT) | **0.861** |

> **돌아보며**: Weighted F1은 다수 클래스(음성)의 영향을 크게 받습니다. 최종 모델의 양성 재현율은 약 23%에 그쳤습니다. 실제 진단 문제라면 양성 클래스의 Recall이나 PR-AUC를 주 지표로 두는 것이 맞습니다. 또 임계값을 같은 검증 세트에서 골랐기 때문에 점수가 다소 낙관적입니다. 별도의 검증 fold에서 정하는 것이 더 정확합니다.

## HW3 · 항공편 지연 확률 예측: 결측 복원 + XGBoost
**80만 건 중 결측이 많은 실데이터라서, 모델링보다 *결측을 논리적으로 복원하는 전처리*에 공을 들였습니다.**

- **결측 복원**
  - 항공사명과 항공사 ID는 서로 1:1로 대응하는 점을 이용해, 한쪽이 비어 있으면 다른 쪽으로 채웠습니다.
  - 출발과 도착 예정 시각 중 하나만 비어 있으면, **같은 노선(출발 공항, 도착 공항)의 평균 비행 시간**으로 역산했습니다. 자정을 넘는 경우도 처리했습니다.
- **피처 정리**: 월과 일을 연중 일자(`date`)로 합쳤습니다. 값이 하나뿐이거나 다른 컬럼과 중복되는 컬럼(Cancelled, Diverted, 각종 ID)은 제거했습니다. 항공사는 원-핫, 공항과 기체 번호는 레이블 인코딩으로 변환했습니다.
- **모델 탐색**: 1만 건 샘플에서 RF · DT · XGBoost · LightGBM을 5-Fold로 비교했습니다. XGBoost는 RandomizedSearchCV(80개 조합)로 튜닝했습니다. 타깃 인코딩도 시도했지만 개선 효과가 없어서 쓰지 않았습니다.
- **최종 학습**: 라벨이 있는 약 20만 건 전체로 `xgb.cv` 조기 종료를 써서 트리 수(1,004개)를 정했습니다. 그 결과 Hold-out Log-Loss **0.4376**을 얻었습니다. 평균 지연률로만 예측할 때는 약 0.48입니다.

> **돌아보며**: 라벨이 없는 약 59만 건은 학습에 쓰지 않았습니다. 이 데이터를 의사 라벨링(pseudo-labeling) 같은 준지도 학습에 활용하는 것이 다음 개선 방향입니다.
